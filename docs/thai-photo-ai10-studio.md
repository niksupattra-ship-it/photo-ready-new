# Thai Studio: manual outfits and photo-scoped AI10

New 159 purchases resolve to `download_159_work_ai10_v3` and retain the original photo's download/full-edit unlock. They grant ten AI processing reservations on that immutable original-photo work, not ten wallet-wide legacy credits. The original completed photo must exist before checkout. Historical explicit package IDs keep their original receipt definitions.

`thai-work-ai-credits.js` creates an additive grant table and nullable work column/index on the existing usage ledger. The paid receipt and ten-use grant are recorded in the same payment transaction, idempotently by payment ID. Reservations serialize by wallet/work, count reserved/completed usage, reject an eleventh request and reject another original or unauthenticated paid use. Expiry follows the existing photo policy: seven days from the first paid right on the work (the payment transaction timestamp on the first purchase); an upgrade or top-up does not extend that window. Checkout checks the owned work is still within that window. Repeated original-work purchases add another ten uses with the same expiry.

Every new Thai paid-work portrait/hairstyle processing request shares this pool, including basic choices. Alternate cosmetic AI processing and the legacy explicit job-outfit AI path also reserve from it. Existing-result replay, submission retry, manual outfit placement, downloads and reopened projects do not reserve a use. Alternate finish uses a stable operation key. Failed/cancelled results release the reservation through existing ledger settlement without minting wallet credits. Concurrent requests and repeated payment notifications cannot multiply the allowance. Existing free watermarked previews and historical entitlements retain their previous behavior outside an AI10 work.

All native/manual Thai Studio outfits are selectable without Pro and without suit-choice limits. Both server manual-suit authorization and UI use this rule; paid AI selections retain their own offer.

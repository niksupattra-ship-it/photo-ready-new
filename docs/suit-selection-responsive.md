# Immediate suit placement without dimming the editor

Choosing a suit previously asserted the editor-wide asset busy flag. This disabled and dimmed controls to 40% opacity, then restored them on completion. The native-only display experiment also made the first changed frame depend on the full image download. Neither behavior matched selecting a visible element in the workspace.

Suit requests now use a separate pending selection. A ready full image or the already decoded bounded garment preview paints before native preparation, fitting and policy requests. The library remains mounted, fully opaque and navigable. The shared blocking busy state still applies to other existing asset operations. Document writes remain guarded while the suit is provisional, with the inspector inert rather than globally dimmed; export/save continue to wait for native source and permission approval. Full-detail source pixels remain the only committed/exported pixels. No artificial loading delay or global progress overlay is added.

Rapid selections cancel the old transaction and retain ownership of its preview until the next one paints. Removing a pending suit cancels that request before committing removal. Late source/policy replies cannot undo the latest choice. The native prefetch remains optional, never a prerequisite to first feedback. All 75 existing catalog templates now include their generated bounded transparent previews in the checkout.

The updated `tests/suit-native-preview.browser.py` holds native downloads and checks immediate stage pixels plus unchanged menu opacity, enabled state, DOM nodes and geometry in English/Thai desktop/mobile and Thai Easy mode. It also checks rapid changes, late replies, rejection rollback and pending removal/undo. The existing eight-case handoff test checks face pixels, approved full-resolution history, rollback and cancellation. These tests use the real local editor/assets and block live APIs, AI, payment and download effects. They do not measure a live user's connection or device latency.

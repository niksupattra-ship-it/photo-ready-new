# Thai outfit AI edits and shared credits

Thai Studio shows an explicit “แก้ไขด้วย AI” action for every catalogue outfit. In Easy Mode, the first outfit selection enters AI setup directly within Easy Mode, without a separate AI button under outfit tiles. It starts with outfits, then requires a hairstyle selection and (for women) a Natural/Makeup choice before displaying Create. Studio uses the same staged sequence after its explicit AI button, including an explicit hairstyle choice for men. Cancelling setup returns the first Easy flow to outfits. Later Easy selections remain manual native outfit changes. Selecting a native outfit remains separate from submitting AI. The full-outfit mode uses `th-full-outfit-ai-v1`; it reuses the complete-portrait rendering engine while preserving the original Thai request as credit authority. Only existing job, government, student and gown asset paths are accepted. Original Thai head-only requests and queued results retain their rendering path.

Thai AI generations (outfit and hairstyle requests) share two free trials per wallet per Bangkok calendar day. Reservations lock the wallet row before counting reserved/completed daily usage or debiting a paid balance. Failures and eligible cancellations refund once. Paid shared credits take precedence when available so paid outputs retain full-edit rights; otherwise free trials are used. A free-slot refund never adds a paid credit. Daily reset is midnight Asia/Bangkok.

New 159-baht purchases use `download_159_ai10_v2`: existing image download/full-edit rights and premium-hair rights are retained, plus ten shared generation uses (`g=10,h=0`). Outfit and hairstyle requests debit that same pool. Frozen `download_159_hair_v1` receipts retain their original zero-AI-credit promise; they are not relabeled or retroactively granted credits. Repeated settlement of one payment grants once, while an explicit additional purchase may add another ten uses. Pending-payment recovery recognizes the new package. Historical duplicate-download refund behavior is unchanged; the new bundle intentionally permits repurchasing AI credits for an already unlocked work.

The existing server-verified owner check grants unlimited AI usage to the configured owner account. The login identity must match both the configured email and request wallet; an email in request JSON or a different wallet does not grant access. The eligibility endpoints use that same check. No customer record is modified manually.

Validation uses inert AI providers, real Chromium UI flows, and isolated PostgreSQL WASM payment/storage tests. Includes all four outfit categories, native-output preservation, male/female staged creation, exhausted entitlement behavior, concurrent quota reservations, actual SQL debits/refunds/reset, payment replay/re-purchase, and authenticated owner bypass. No live AI generation, production database writes, or customer payment occurred during testing.

## Studio processing stability

Background suit entitlement synchronization is keyed to the actual account, output, selected suit, entitlement revision and processing state rather than a changing callback on every progress render. The check is suspended during generation; explicit export and selection checks still use the server. After a Thai full-outfit AI result, PNG suit selections remain manual and no longer queue an implicit AI job. Explicit hair/finish changes retain full-outfit composition and reuse the existing same-job finish rules where eligible. Credit reservation, package prices and provider prompts are unchanged. These regression tests do not confirm live image delivery.

## English full-outfit preparation parity

New Thai full-outfit jobs send `th-en-outfit-preparation-parity-v1` while retaining their Thai credit-authority locale and existing charged submission identity. The client uses the same full-outfit model warm-up, segmentation decision, finish/framing cache revisions, generation fields and native-output completion path as English. Earlier Thai keep-upload requests added an extra full-upload hair reference that English did not send; the new opt-in version uses exactly the English reference path. Unversioned pending jobs retain their original references.

Tests now compare actual browser form construction through the production renderer, as well as twelve male/female, Natural/Makeup and hairstyle/current-hair combinations. For identical source, outfit and choices, the base head/body board, provider prompt, reference bytes and output size must match English. No preset head shrink, extra AI call or automatic local head warp is added. Generated PNGs retain their native dimensions and bytes through completion.

The server returns its stored preparation version. It is preserved on completed layers and saved metadata, so explicitly pressing Create for an old Thai result can generate through the new preparation rather than silently reusing the old result. Current-version results still reuse without another request. Previously purchased/queued results are not relabeled, automatically regenerated or automatically charged. Live AI appearance is not proven by inert-provider tests.

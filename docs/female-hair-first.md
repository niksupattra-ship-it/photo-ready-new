# Female V6: head and hair before skin finishing

New female requests use `studio-original-ai-v6`. Male processing and released female V1–V5 requests keep their existing prompts and processing order. Existing results retain their real version; V5 results do not satisfy a V6 cache lookup. Saved V5 shared bases remain readable for the existing cosmetic controls.

1. Generate the head, selected hairstyle and existing wide/deep U-shaped neck/clavicle backing from the untouched owned upload. Keep the existing hairstyle construction wording, identity reference and neck geometry guide. Defer skin finishing and cosmetics.
2. Send that completed PNG as the sole identity/geometry/hair authority for skin finishing. The only other image is the identity-free skin/light guide. Repair face, ears and the entire neck backing together. Remove all moles, freckles, dark/red spots, acne and acne marks, including permanent identifying spots; no mark-preservation exception applies. Lock hair, facial anatomy/eyes/expression, neck boundary, dimensions, framing and temporary background. Keep delicate photographic texture and soft continuous studio light.
3. Matting and edge cleanup run only after both edits succeed. The existing outfit composition, shared Natural base and local cosmetic choices remain unchanged.

The same customer job contains both AI calls. Neither phase retries or delivers an intermediate result. A failure, empty result or changed final dimensions fails before matting; existing server settlement/refund rules apply. Both guides are loaded before the first provider call. Model, 2K output setting, ownership, payment and download rules are unchanged.

Validation: `scripts/check-female-hair-first.mjs` exercises the actual production entry point and transport payload order with inert provider calls, all four finish modes, default/catalogue/free-PNG hairstyles, phase failures, output-size rejection and version/cache/saved-base compatibility. Existing V5 and older request tests remain pinned to their released versions. These tests establish orchestration and prompt constraints, not visual fidelity of a live model output; no paid generation is performed.

# รักษาเมคอัพเดิมเมื่อเปลี่ยนทรงผม — เฉพาะหญิงที่เลือกแต่งหน้า

วันที่จัดทำ: 23 ตุลาคม 2026

## สาเหตุที่ตรวจพบ

ค่า makeup ยังส่งครบในเส้นทาง Studio ที่ตรวจ แต่คำขอเปลี่ยนผมเดิมสร้างภาพใหม่จากรูปดิบ + ภาพทรงผม + คำอธิบายแต่งหน้า โดยไม่มีภาพเมคอัพที่ยอมรับจากครั้งแรกเป็นแนวทาง จึงมีช่องให้ AI สร้างสีปาก สีตา ความเข้ม และแสงต่างออกไป หรือดูเหมือนไม่ได้แต่งหน้า ทั้งที่ค่าโหมดยังเป็น makeup

## สิ่งที่แก้

- ผูกผลแต่งหน้าครั้งแรกกับไฟล์ต้นฉบับของคนนั้น และใช้เป็นแนวทางต่อเนื่องเมื่อเปลี่ยนผม ไม่เปลี่ยนไปอ้างอิงผล AI ครั้งล่าสุดสะสมกัน
- เตรียมภาพบริเวณคิ้วถึงคาง ขนาดสูงสุด 512px และข้อมูลไม่เกิน 512KB ปิดส่วนผมที่โมเดลตรวจพบในภาพแนวทางเท่านั้น ภาพต้นฉบับและผลลัพธ์ไม่ถูกทาสีหรือปะหน้า
- คำขอเดียวส่งรูปดิบเป็นแหล่งอัตลักษณ์ ภาพทรงที่เลือกเป็นแหล่งทรงผม และภาพเมคอัพเป็นแหล่งสี ความเข้ม ผิว และแสงที่ยอมรับแล้ว
- แยกแคชตามภาพเมคอัพต้นทาง ใช้ทรงที่เคยทำได้ตามเดิม ตรวจซ้ำหลังรอเตรียมภาพเพื่อไม่ให้ใช้ข้อมูลของรูป A กับรูป B
- ใช้กับการกลับไปเลือกผมเดิมด้วย เมื่อเปิดงานที่บันทึกไว้จะผูกแนวทางกับภาพงานที่เปิดคืนได้ ไม่มีการดึงเมคอัพของงานก่อนหน้ามาใช้
- เซิร์ฟเวอร์ตรวจรูปแนวทางและลบข้อมูลภาพนี้ออกจาก job fields เมื่อสำเร็จ ล้มเหลว หรือยกเลิก

เพิ่มเพียงภาพแนวทางในคำขอสร้างภาพเดิม ไม่เพิ่มการเรียกโมเดลสร้างภาพอีกครั้งต่อการเปลี่ยนผม นโยบายคิดเครดิตในระบบและ SQL จัดการเครดิตเดิมไม่ได้เปลี่ยน ไม่มีการเพิ่มโมเดล AI แบบเสียเงินเพื่อวิเคราะห์เมคอัพ

## ไฟล์ที่ต้องแทนที่พร้อมกัน

1. src/main.jsx
2. production-portrait-pipeline.js ที่รากโปรเจ็ก (ไม่ใช่สำเนาใน src)
3. seedream-review-transport.js ที่รากโปรเจ็ก
4. job-store.js ที่รากโปรเจ็ก

แตก ZIP ทับที่รากโปรเจ็กฐานข้างต้น เก็บไฟล์อื่นไว้ตามเดิม แล้ว build/deploy ด้วยขั้นตอนเดิมของโปรเจ็ก ถ้า build เองให้ใช้ npm ci และ npm run build จากนั้น restart เซิร์ฟเวอร์ ต้องมีทั้ง client และ server รุ่นใหม่ แล้วโหลดหน้า Studio ใหม่หลังบันทึกงานที่ต้องการเก็บก่อน ไม่มีการแก้ฐานข้อมูลหรือการตั้งค่า key

ไฟล์ใน scripts และ VERIFY-female-makeup-hair-continuity.json เป็นชุดตรวจและรายงาน ไม่ใช่ไฟล์ runtime

## การตรวจที่ผ่าน

- ชุดทดสอบ client ใหม่ 15 กรณี และ server ใหม่ 8 กลุ่ม: ตรวจคำขอจริงผ่าน mock provider การเรียงภาพ JPEG ขนาด/ชนิดข้อมูล การกลับผมเดิม การแยกรูป A/B การยกเลิกและแคช
- ชุดตรวจรูปใหม่/อัตลักษณ์/ทรงผม/ขอบชุด/เครดิต/สิทธิ์เดิมผ่าน รายการอยู่ใน VERIFY
- Canvas และ MediaPipe จริง 8 กรณี: Chromium และ WebKit อย่างละ 4 ภาพ รวมหน้าม้าและภาพ 2560×2560 ต้นฉบับไม่เปลี่ยนพิกเซล แนวทางใหญ่สุด 512×435 และ 35,027 ตัวอักษร
- PostgreSQL WASM จริง 11 กรณีบนข้อมูลจำลอง: ลบเฉพาะภาพแนวทาง ผลลัพธ์ สถานะงาน ยอดเงิน ledger และ trial เทียบกับฐานแล้วคงพฤติกรรมเดิม
- npm run build ผ่าน 118 modules มีคำเตือนขนาด bundle เดิม ไม่มี build error

## ขอบเขตที่ยังต้องตรวจหลังติดตั้ง

ยังไม่ได้ deploy ขึ้นเว็บไซต์หรือเรียก AI สร้างภาพจริงในการทดสอบรอบนี้ ชุดตรวจยืนยันการส่งภาพแนวทางและการแยกสถานะ ไม่ยืนยันว่าโมเดลจะคงเมคอัพเหมือนกันทุกพิกเซล/ทุกภาพ การตรวจผมอาจเหลือเศษผมที่โมเดลไม่จัดเป็นผม จึงมีคำสั่งให้ AI ละเว้นผมเดิมในภาพแนวทางด้วย การทดสอบ WebKit ไม่ใช่การทดสอบบน iPhone/iPad จริง

หลังติดตั้งให้ทดสอบภาพเดิม: แต่งหน้าครั้งแรก → เลือกทรงผมใหม่ → เลือกอีกทรง → กลับทรงที่เคยทำ แล้วเพิ่มรูปคนใหม่เพื่อตรวจว่าสีตา/ปาก/แสงยึดงานของคนนั้น ขณะเดียวกันทรงผมต้องยึดแบบที่เลือก
